# tistory-comment-spam-cleaner

티스토리 블로그에 대량으로 등록된 도배·스팸 댓글을 수집하고, 규칙에 따라 분류한 뒤 화면에서 직접 확인하여 안전하게 일괄 삭제할 수 있도록 만든 Python 기반 로컬 웹 서비스입니다.

특정 게시글만 확인할 수도 있고 `sitemap.xml`을 이용해 블로그 전체 게시글을 탐색할 수도 있습니다. 삭제 전에는 대상 댓글을 JSON/CSV로 백업하고, 삭제 후에는 댓글을 다시 조회해 실제 삭제 여부를 확인합니다.

> 이 프로젝트는 카카오/티스토리의 공식 도구가 아닙니다. 반드시 본인이 관리 권한을 가진 티스토리 블로그에서만 사용하세요. 댓글 삭제는 되돌릴 수 없습니다.

자세한 개발 배경과 동작 분석은 아래 블로그 글에 정리했습니다.

- 블로그: https://lsjsj92.tistory.com/725

## 만든 배경

2026년 8월 8일 저녁, 약 4시간 동안 제 티스토리 블로그 여러 게시글에 수천 건의 댓글이 반복해서 등록되는 일이 발생했습니다.

전체 게시글을 다시 수집해 확인한 결과는 다음과 같았습니다.

| 항목 | 결과 |
|---|---:|
| 피해 게시글 | 13개 |
| 수집된 전체 댓글 | 5,622건 |
| 도배로 분류된 댓글 | 5,571건 |
| 정상 댓글 | 51건 |
| 도배 집중 시간 | 2026-08-08 20:03 ~ 23:55 |

댓글 닉네임에는 `PG_SLEEP`, `waitfor delay`, `sleep()` 등 SQL Injection 취약점 확인에 사용되는 문자열이 반복해서 포함되어 있었습니다. 일반적인 광고성 댓글이라기보다 자동화된 스캐너가 댓글 입력창을 대상으로 요청을 반복한 형태로 보였습니다.

  <img src="asset/spam-public-comments.PNG" width="48%" alt="블로그 댓글 영역에 반복 등록된 댓글">
</p>

문제는 댓글을 정리하는 과정이었습니다. 티스토리 관리 화면에서는 수천 건의 댓글을 하나씩 처리해야 했고, 신고 처리된 댓글도 `운영정책 위배로 관리자 삭제되었습니다.`라는 문구로 바뀔 뿐 댓글 항목 자체는 그대로 남아 있었습니다.

그래서 단순히 댓글을 빠르게 지우는 스크립트가 아니라 다음 흐름을 한 번에 처리하는 서비스를 만들었습니다.

```text
게시글 탐색 → 댓글 수집 → 스팸 분류 → 삭제 대상 확인 → 백업 → 일괄 삭제 → 재조회 검증
```

## 서비스 화면

서비스는 별도의 Node.js나 프론트엔드 빌드 과정 없이 Python 서버를 실행하면 브라우저에서 바로 사용할 수 있습니다.

기본 접속 주소는 다음과 같습니다.

```text
http://127.0.0.1:8765
```

### 게시글별 모니터링

등록된 게시글마다 전체 댓글 수, 활성 댓글 수, 삭제된 댓글 수, 스팸/의심 댓글 수, 최초·최종 작성 시각을 한 화면에서 확인할 수 있습니다.

`sitemap.xml`을 이용하면 블로그 전체 게시글을 탐색할 수 있기 때문에, 사용자가 미처 확인하지 못한 과거 게시글의 도배 댓글도 함께 찾을 수 있습니다.

  <img src="asset/main-monitoring.PNG" width="100%" alt="게시글별 댓글 모니터링 화면">
</p>

### 삭제 확인

댓글을 선택하고 삭제를 눌러도 바로 삭제가 실행되지는 않습니다.

삭제 대상 수와 스팸/의심/정상 댓글 수를 먼저 보여주며, 사용자가 `삭제`라는 문구를 직접 입력해야 실제 삭제 버튼이 활성화됩니다. 삭제 직전에는 대상 댓글을 JSON과 CSV로 백업합니다.

<p align="center">
  <img src="asset/delete-confirmation.PNG" width="60%" alt="대량 댓글 삭제 전 최종 확인 화면">
</p>

삭제가 시작되면 성공/실패/남은 건수와 진행률을 화면에서 확인할 수 있습니다. 작업이 끝난 뒤에는 댓글을 다시 조회해 실제로 삭제되었는지도 확인합니다.

|---|---|
| 블로그 전체 게시글 탐색 | `sitemap.xml`을 읽어 블로그의 게시글을 자동으로 찾습니다. |
| 댓글 전체 수집 | 특정 게시글 또는 등록된 여러 게시글의 댓글을 수집합니다. |
| 규칙 기반 스팸 분류 | 작성 시간, 닉네임, 본문, 반복 작성 횟수, 분당 댓글 수 등의 조건으로 점수를 계산합니다. |
| 댓글 검색 및 필터링 | 게시글, 작성 기간, 닉네임, 본문, 스팸 등급, 삭제 상태 등으로 댓글을 필터링합니다. |
| 삭제 대상 직접 선택 | 자동으로 전부 삭제하지 않고 사용자가 화면에서 최종 대상을 확인하고 선택합니다. |
| 정상 댓글 보호 | 정상 등급 댓글이나 운영자 답글이 잘못 포함되지 않도록 삭제 전에 다시 확인합니다. |
| 삭제 전 자동 백업 | 실제 삭제 전에 대상 댓글을 JSON/CSV 파일로 저장합니다. 백업에 실패하면 삭제를 시작하지 않습니다. |
| 대량 삭제 | 요청 속도와 동시 실행 수를 제한하면서 댓글을 순차적으로 삭제합니다. |
| 진행 상태 모니터링 | 삭제 성공/실패/남은 건수와 진행률을 실시간으로 확인할 수 있습니다. |
| 중단 및 재개 | 세션 만료나 연속 오류가 발생하면 작업을 중단하고, 문제 해결 후 남은 항목부터 재개할 수 있습니다. |
| 삭제 후 검증 | 작업이 끝난 뒤 댓글을 다시 수집해 실제 삭제 상태와 비교합니다. |
| 세션 쿠키 보호 | 티스토리 로그인 세션 쿠키를 로컬 DB에 암호화하여 저장합니다. |

## 스팸 분류 규칙

스팸 판정 규칙은 `config/rules.yaml`에서 수정할 수 있습니다.

기본적으로 각 규칙에 가중치를 부여하고, 여러 조건이 함께 일치할수록 점수가 높아지는 방식입니다.

예시는 다음과 같습니다.

```yaml
rules:
  - id: attack-window
    description: 댓글 도배가 집중된 시간대
    weight: 55
    when:
      written_between:
        start: "2026-08-08 20:00"
        end: "2026-08-08 23:59"

  - id: empty-content
    description: 닉네임만 있고 본문이 비어 있는 댓글
    weight: 40
    when:
      content_equals: ""
```

작성 시각뿐 아니라 닉네임/본문 정규식, 완전 일치, 동일 닉네임 반복 횟수, 분당 댓글 수, 비밀댓글 여부, 대댓글 여부 등을 조건으로 사용할 수 있습니다.

다른 블로그에서 사용할 때는 특히 `attack-window`를 본인이 실제로 도배를 당한 시간대로 수정한 뒤 분류 결과를 확인하는 것을 권장합니다.

## 설치 및 실행

### 요구 환경

- Python 3.9 이상
- 본인 티스토리 블로그에 로그인할 수 있는 브라우저
- Windows / macOS / Ubuntu

별도의 Node.js나 데이터베이스 서버는 필요하지 않습니다.

### 설치

```bash
git clone https://github.com/lsjsj92/tistory-comment-spam-cleaner.git
cd tistory-comment-spam-cleaner

python -m venv .venv
```

macOS / Ubuntu:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

패키지를 설치합니다.

```bash
pip install -r requirements.txt
```

기존에 사용하는 conda 환경이 있다면 별도의 가상환경을 만들지 않고 해당 환경에서 설치해도 됩니다.

### 실행

```bash
python -m app
```

정상적으로 실행되면 기본적으로 아래 주소로 서버가 열리고 브라우저가 실행됩니다.

```text
http://127.0.0.1:8765
```

포트를 변경하거나 브라우저 자동 실행을 끄고 싶다면 다음과 같이 실행할 수 있습니다.

```bash
python -m app --port 9000 --no-browser
```

## 환경 설정

### 1. `.env` 설정

첫 실행 시 `.env` 파일과 암호화에 필요한 키가 자동으로 생성됩니다.

가장 먼저 확인해야 할 값은 `APP_BLOG_URL`입니다.

```env
APP_BLOG_URL=https://내블로그.tistory.com
```

본인의 티스토리 블로그 주소로 변경한 뒤 애플리케이션을 다시 실행합니다.

`APP_SECRET_KEY`는 로그인 세션 쿠키를 로컬 DB에 암호화해서 저장할 때 사용하는 값입니다. 첫 실행 시 생성된 값을 그대로 사용하는 것을 권장합니다. 값을 임의로 변경하면 기존에 저장된 쿠키를 다시 등록해야 할 수 있습니다.

기본 서버 주소는 `127.0.0.1`이며 로컬 PC에서만 접근하도록 되어 있습니다. 외부 접속이 꼭 필요한 경우에만 `APP_HOST=0.0.0.0`과 인증 설정을 사용하세요. 세션 쿠키를 다루는 서비스이므로 공개망 노출은 권장하지 않습니다.

그 외 환경 변수와 기본값은 `.env.example`을 참고하세요.

### 2. 티스토리 로그인 세션 등록

댓글 조회는 공개 요청으로 가능하지만, 댓글 삭제에는 블로그 소유자의 로그인 세션이 필요합니다.

카카오 계정의 아이디와 비밀번호를 프로그램에 직접 입력하는 방식은 사용하지 않습니다. 브라우저에서 정상적으로 로그인한 뒤 만들어진 세션 쿠키를 가져와 사용합니다.

1. 브라우저에서 본인 티스토리 블로그에 로그인합니다.
2. `F12`를 눌러 개발자도구를 엽니다.
3. `Network` 탭에서 페이지를 새로고침합니다.
4. 본인 블로그 주소로 시작하는 요청을 선택합니다.
<p align="center">
  <img src="asset/f12-network-check.PNG" width="48%" alt="개발자도구 네트워크 정보">
</p>
5. 우클릭 후 `Copy` → `Copy as cURL`을 선택합니다.
<p align="center">
  <img src="asset/copy-curl-1.PNG" width="48%" alt="cURL 복사">
</p>
6. 서비스의 `설정` 화면에서 쿠키 등록 영역에 그대로 붙여넣습니다.
<p align="center">
  <img src="asset/copy-curl-2.PNG" width="48%" alt="cURL 붙여넣기">
</p>
7. `소유자 인증됨` 상태가 표시되는지 확인합니다.

복사한 cURL에는 로그인 세션 정보가 포함될 수 있으므로 다른 사람에게 공유하지 마세요.

### 3. `config/rules.yaml` 설정

다른 블로그에서 사용할 때는 기본 규칙을 그대로 사용하기보다 실제 도배 패턴에 맞게 확인하는 것이 좋습니다.

특히 아래 항목을 우선 확인하세요.

- `attack-window`: 실제 도배가 발생한 시간대
- 닉네임 패턴: 반복되는 닉네임 또는 Injection 문자열
- 본문 패턴: 반복되는 문구 또는 빈 본문
- 반복 횟수 조건: 동일 닉네임, 분당 댓글 수 등
- 화이트리스트: 삭제 대상에서 반드시 제외할 닉네임 또는 댓글

규칙은 `config/rules.yaml`에서 직접 수정하거나 서비스의 설정 화면에서 편집할 수 있습니다.

## 사용 방법

<p align="center">
  <img src="asset/delete-process.PNG" width="48%" alt="삭제 진행 중">
</p>

### 1. 게시글 등록

`게시글 관리`에서 댓글을 확인할 게시글의 URL 또는 글 번호를 등록합니다.

블로그 전체를 확인하려면 `sitemap 전체 스캔`을 사용합니다.

### 2. 댓글 수집

등록된 게시글을 선택한 뒤 댓글을 수집합니다.

수집이 끝나면 게시글별 댓글 수와 스팸/의심 분류 결과를 확인할 수 있습니다.

### 3. 분류 결과 확인

`댓글 관리` 화면에서 게시글, 작성 기간, 닉네임, 본문, 스팸 등급 등으로 필터링합니다.

대량 삭제를 실행하기 전에 실제 독자의 정상 댓글이 스팸으로 분류되지 않았는지 반드시 확인하세요.

### 4. 1건 시험 삭제

대량 삭제 전에 `설정` 화면의 시험 삭제 기능으로 스팸 댓글 1건을 먼저 삭제해 보는 것을 권장합니다.

시험 삭제는 드라이런이 아니라 실제 삭제입니다. 반드시 삭제해도 되는 댓글 번호를 사용하세요.

### 5. 대량 삭제

삭제할 댓글을 선택한 뒤 삭제 작업을 생성합니다.

실제 실행 전에는 다음 내용을 다시 확인합니다.

- 전체 삭제 대상 수
- 스팸/의심/정상 등급별 건수
- 정상 댓글 또는 운영자 답글 포함 여부
- 백업 생성 여부

최종 확인 창에서 `삭제`를 직접 입력해야 실제 삭제가 시작됩니다.

### 6. 진행 상황과 결과 확인

삭제 중에는 진행률과 성공/실패/남은 건수를 확인할 수 있습니다.

연속 실패가 발생하면 작업이 자동으로 중단될 수 있습니다. 세션이나 네트워크 상태를 확인한 뒤 남은 작업부터 재개할 수 있습니다.

작업이 끝나면 댓글을 다시 조회해 실제 삭제 여부를 검증합니다.

## 주의사항

- 본인이 관리 권한을 가진 티스토리 블로그에서만 사용하세요.
- 댓글 삭제는 되돌릴 수 없습니다.
- JSON/CSV 백업은 삭제 대상을 기록하기 위한 것이며 티스토리 댓글을 원래 상태로 복원해 주는 기능은 아닙니다.
- 대량 삭제 전에는 반드시 분류 결과를 확인하고 1건 시험 삭제부터 진행하세요.
- 세션 쿠키와 `Copy as cURL` 결과를 다른 사람에게 공유하지 마세요.
- 이 프로젝트는 카카오/티스토리의 공식 API가 아니라 실제 웹 요청을 기반으로 동작하므로, 티스토리의 요청 방식이 변경되면 동작하지 않을 수 있습니다.
