# tistory-comment-spam-cleaner

티스토리 블로그에 매크로로 쏟아진 스팸 댓글을 수집해서 눈으로 확인하고, 정상 댓글은
남긴 채 원하는 것만 안전하게 일괄 삭제하는 도구입니다. 파이썬만 있으면 내 컴퓨터에서
바로 돌아갑니다.

> **비공식 도구입니다.** 카카오 / 티스토리와 아무 관계가 없고, 승인이나 지원을 받지
> 않았습니다. `Tistory` 는 Kakao Corp. 의 상표입니다. 본인이 관리 권한을 가진 블로그에만
> 쓸 수 있습니다.

**📖 만든 과정과 자세한 이야기 → [블로그 글](https://lsjsj92.tistory.com/725)**

이 문서는 "이게 뭐고 어떻게 쓰는지"만 다룹니다. 사고 전말, 티스토리 내부 요청을 분석한
과정, 설계 판단 같은 이야기는 위 글에 있습니다.

## 왜 만들었나

2026년 8월 8일 저녁 8시 3분부터 밤 11시 55분까지, 약 4시간 동안 제 블로그 글 13개에
매크로 댓글이 쏟아졌습니다. 나중에 실제로 수집해서 세어 보니 **5,571건**이었습니다.

닉네임을 보면 사람이 쓴 게 아니라는 걸 바로 알 수 있습니다.

```
GRLpGpAGykOXRFmb') OR 54=(SELECT 54 FROM PG_SLEEP(15))--
GRLpGpAG-1 waitfor delay '0:0:15' --
GRLpGpAG0"XOR(if(now()=sysdate(),sleep(15),0))XOR"Z
-1' OR 5*5=25 --
```

SQL 인젝션 문자열입니다. 자동화된 취약점 스캐너가 댓글창을 입력 필드로 삼아 긁고 지나간
흔적입니다. 이 중 한 닉네임(`GRLpGpAG`) 하나로만 4,815건이었습니다.

처음에는 피해 글이 11개인 줄 알았는데요. 이 도구에 넣은 `sitemap.xml` 전체 스캔을
돌려 보고서야 제가 모르던 글 2개에도 도배가 들어와 있다는 걸 알았습니다. 실제 피해
게시글은 13개였습니다.

### 지우려고 했는데 방법이 없었습니다

| 시도한 것 | 결과 |
|---|---|
| 티스토리 고객센터 문의 | 일괄 삭제를 지원하지 않는다는 답변을 받았습니다 |
| 관리 화면에서 직접 삭제 | 댓글 하나마다 팝업을 열고 탭을 눌러 확인해야 합니다. 5,000건이면 물리적으로 불가능합니다 |
| 스팸 신고 | 본문만 `운영정책 위배로 관리자 삭제되었습니다.` 로 바뀝니다. 댓글 자체는 남아서 글마다 빈 껍데기 수백 개가 계속 보입니다 |
| Open API | 종료됐습니다. 공식적인 프로그램 접근 경로가 없습니다 |

신고로 해결되지 않는다는 게 결정적이었습니다. 5,380건이 그렇게 껍데기만 남은
상태였습니다. 결국 직접 만들었고, 같은 일을 겪는 분이 그대로 쓸 수 있게
일반화했습니다.

## 무엇이 진짜 어려웠나

"5,000건 삭제"는 어렵지 않습니다. 반복문 하나면 됩니다.

어려운 건 **수집한 5,622건 사이에 섞인 정상 댓글 51건을 안 지우는 것**입니다.
독자분이 남긴 진짜 댓글 32건, 제가 쓴 답글 19건. 이걸 하나라도 날리면 복구할 방법이
없습니다.

이 도구가 공들인 부분은 전부 여기에 있습니다.

- 규칙으로 스팸 점수를 매겨 **등급을 나눕니다.** 무조건 지우지 않습니다
- 지우기 전에 **화면으로 눈으로 확인**하고 체크박스로 고릅니다
- 정상 등급 댓글이 대상에 섞이면 **서버가 거부합니다.** 몇 건인지 보여주고, 제가 확인해서 명시적으로 허용해야만 진행됩니다
- 제가 쓴 답글은 **선택 자체가 불가능**합니다
- 삭제 직전 대상 전체를 **JSON + CSV로 자동 백업**합니다. 백업이 실패하면 삭제를 시작하지 않습니다
- 삭제 후 **다시 조회해서 진짜 사라졌는지 검증**합니다

실제 결과는 5,622건 판정에 **오분류 0건**이었습니다.

본문 없이 공감만 누르고 간 실제 독자분이 있었는데요. 그 댓글도 살아남았습니다.
"본문이 비어 있음" 규칙은 단독으로는 스팸이 되지 않게 가중치를 낮춰 뒀기 때문입니다.

## 할 수 있는 일

- 글 하나씩, 또는 `sitemap.xml` 로 블로그 전체 글의 댓글을 **수집**
- 기간, 닉네임, 본문, 스팸 등급으로 **걸러 보기**
- 규칙 파일로 **스팸 점수 매기기** — 도배 시간대, 인젝션 문자열, 반복 작성자, 분당 폭주, 링크 도배
- 삭제 전 **자동 백업** (JSON + CSV)
- 속도를 제한하며 **일괄 삭제**, 진행률 실시간 표시
- 삭제 후 **재조회 검증**
- 서버를 꺼도 작업 상태가 남아 **중단 지점부터 재개**
- 주기적으로 재수집해 **같은 공격이 재발하는지 감시**

화면은 웹 UI이고 `127.0.0.1:8765` 로 열립니다.

## 시작하기

필요한 건 두 가지뿐입니다.

- **Python 3.9 이상**
- **본인 티스토리 블로그에 로그인된 브라우저** (Chrome, Edge, Firefox 등)

Node.js나 별도 빌드 도구는 필요 없습니다. Windows, macOS, Ubuntu 모두에서 돌아갑니다.

### 설치

```bash
git clone https://github.com/lsjsj92/tistory-comment-spam-cleaner.git
cd tistory-comment-spam-cleaner
python3 -m venv .venv
source .venv/bin/activate          # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

이미 쓰시는 conda 환경이 있으면 새로 만들지 않고 그 환경에 그대로 설치하셔도 됩니다.

### 실행

```bash
python -m app
```

첫 실행에서 `.env` 가 자동으로 만들어지고 암호화 키가 채워집니다. 그다음 `.env` 를 열어
본인 블로그 주소를 넣고 다시 실행합니다.

```
APP_BLOG_URL=https://내블로그.tistory.com
```

브라우저가 자동으로 열립니다. 포트를 바꾸거나 자동 열기를 끄려면
`python -m app --port 9000 --no-browser` 를 쓰시면 됩니다.

## 사용 순서

### 1. 세션 쿠키 등록

댓글 삭제에는 블로그 소유자 권한이 필요합니다. 티스토리는 카카오 로그인이라 스크립트로
로그인할 수 없어서, **이미 로그인된 브라우저의 쿠키를 가져다 씁니다.**

1. 브라우저에서 본인 블로그에 로그인
2. 블로그 글 아무 곳에서 `F12` → `Network` 탭 → 새로고침
3. 아무 요청이나 우클릭 → `Copy` → **`Copy as cURL`**
4. 이 도구의 `설정` 화면 쿠키 입력란에 그대로 붙여넣고 `등록`

붙여넣기 형식은 가리지 않습니다. cURL 3종(bash / cmd / PowerShell), `Cookie:` 헤더 한 줄,
`name=value; ...` 원문, 개발자도구 JSON 배열을 모두 알아서 인식합니다.

`pip install browser-cookie3` 을 해 두시면 `브라우저에서 자동 가져오기` 버튼 한 번으로
끝납니다.

등록하면 바로 진단이 돕니다. **`소유자 인증됨`** 이 떠야 삭제를 시작할 수 있습니다.

> 쿠키는 `.env` 의 `APP_SECRET_KEY` 로 암호화해서 로컬 DB에 저장합니다. 화면과 로그
> 어디에도 값이 나오지 않습니다. 외부로 전송되는 곳도 없습니다.

### 2. 1건만 시험 삭제

`설정` 화면 아래쪽 `시험 삭제` 에 스팸 댓글 번호 하나를 넣고 실행합니다. 수천 건을
돌리기 전에 권한과 응답이 정상인지 확인하는 절차입니다.

**이건 드라이런이 아니라 실제로 지웁니다.** 반드시 스팸 댓글 번호를 넣으셔야 합니다.

### 3. 게시글 등록하고 수집

`게시글 관리` 에서 글 주소나 글번호를 넣어 추가합니다. `sitemap 전체 스캔` 을 누르면
블로그의 모든 글을 자동으로 찾습니다. 그다음 `선택 게시글 수집` 을 누르시면 됩니다.

수집은 로그인 없이도 되는 공개 조회를 씁니다. **글 하나에 800건이면 약 8초**
걸렸습니다.

### 4. 확인하고 골라서 삭제

`댓글 관리` 에서 게시글과 기간을 지정합니다. 제 경우엔 이랬는데요.

```
기간: 2026-08-08 20:00 ~ 2026-08-08 23:59
스팸 등급: 스팸
```

`필터 결과 전체 선택` 으로 한 번에 고르고, 남길 게 있으면 체크를 해제합니다.

> ⚠️ **스팸 등급 필터를 반드시 함께 걸어 주세요.** 정상 댓글에는 보호 표식이 없어서,
> 등급 조건 없이 전체 선택하면 그 댓글들도 대상에 들어갑니다. 서버가 이 경우를 막고
> "스팸으로 분류되지 않은 댓글 N건이 섞여 있습니다" 라고 거부하는데요, **이 경고가 뜨면
> 그냥 넘기지 마시고 어떤 댓글인지 먼저 확인해 주세요.** 도배를 정리하다 진짜 독자
> 댓글이 딸려 들어가는 사고가 가장 흔합니다.

먼저 **드라이런**으로 대상 건수를 확인하고, 끄고 실제로 실행합니다. 실행 전 확인 창에
`삭제` 를 직접 입력해야 진행됩니다. 그 직후 대상 전체가 `data/backups/` 에 저장됩니다.

**기본 속도(초당 4건)에서 1,000건당 약 4분** 걸립니다. 5,000건이면 20분쯤입니다.

### 5. 결과 확인

`작업 이력` 에서 성공 / 실패 / 남은 항목을 봅니다. 실패한 것만 골라 재시도할 수 있습니다.
연속 실패가 쌓이면 작업이 자동으로 멈추니, 원인을 해결하고 `재개` 를 누르시면 남은
항목부터 이어서 돕니다.

## 실수로 정상 댓글을 지우면 어떻게 되나

삭제는 되돌릴 수 없습니다. 그래서 겹겹이 막아 뒀습니다.

| 장치 | 내용 |
|---|---|
| 드라이런 기본값 | 실제 요청 없이 대상만 확인 |
| 확인 문구 입력 | `삭제` 를 직접 타이핑해야 시작 |
| **정상 등급 차단** | 스팸이 아닌 댓글이 섞이면 거부. 건수와 예시를 보여주고 확인해야만 진행 |
| 빈 조건 차단 | 조건 없는 삭제 요청은 거부 |
| 자동 백업 | JSON + CSV 저장. 백업 실패 시 삭제 시작 안 함 |
| 운영자 댓글 보호 | 내가 쓴 답글은 선택 자체가 불가능. 재수집으로도 안 풀림 |
| 화이트리스트 | 규칙 파일에 지정한 닉네임·댓글은 서버에서 한 번 더 걸러냄 |
| 실행 직전 재확인 | 작업을 만든 뒤 규칙이 바뀌었어도 실행 직전에 다시 걸러냄 |
| 서킷 브레이커 | 연속 실패가 임계치에 닿으면 자동 중단 |
| 사후 검증 | 삭제 후 재조회해서 남아 있으면 실패로 되돌림 |

이 중 **정상 등급 차단**이 가장 중요합니다. 필터를 바꾼 뒤 이전 선택이 남아 있는 상태로
삭제하면 조용히 섞여 들어가는데요, 그걸 막는 마지막 방어선입니다.

백업 파일이 있으니 무엇이 지워졌는지는 항상 추적할 수 있습니다. 다만 **티스토리에 복원
기능이 없어서 되살릴 수는 없습니다.** 백업은 기록용입니다.

## 실제로 어디까지 확인했나

과장 없이 적습니다. 2026-08-17 기준입니다.

| 항목 | 상태 |
|---|---|
| 자동화 테스트 | 461개 통과 (Python 3.9). 테스트 코드는 저장소에 포함하지 않았습니다 |
| 댓글 수집 | 5,622건 (글 13개) |
| 스팸 분류 | 스팸 5,571건 / 정상 51건, **오분류 0건** |
| 소유자 인증 | 확인 |
| 1건 시험 삭제 | 성공 |
| 소규모 실제 삭제 | 9건. 재조회로 사라진 것 확인 |
| 전체 삭제 | **아직 실행하지 않았습니다** (남은 5,562건) |

즉 삭제 경로 자체는 실제 블로그에서 동작을 확인했지만, 수천 건 규모의 연속 실행은
아직 돌려보지 않은 상태입니다. 테스트는 전부 목킹된 응답으로 돌아가며 실제 티스토리를
호출하지 않습니다.

## 자주 궁금해하는 것

**내 블로그가 아닌 곳에도 쓸 수 있나요?**
안 됩니다. 삭제에는 해당 블로그 **소유자의 세션 쿠키**가 필요합니다. 남의 블로그를
대상으로 쓰는 건 불법이고, 그렇게 쓸 수 있게 만들어지지도 않았습니다.

**쿠키를 넘기는 게 안전한가요?**
내 컴퓨터 안에서만 돕니다. 쿠키는 암호화해서 로컬 SQLite에 저장하고, 외부로 보내는
경로가 없습니다. 코드를 직접 확인하실 수 있습니다. 걱정되시면 작업을 마친 뒤 티스토리에서
로그아웃하시면 쿠키가 무효화됩니다.

**티스토리가 막으면 어떻게 되나요?**
블로그 화면이 실제로 쓰는 요청을 그대로 사용하므로, 그 요청이 바뀌면 동작하지 않습니다.
비공식 도구의 태생적 한계입니다. 요청 속도 기본값은 부담을 주지 않는 선으로 잡아 뒀고,
무리하게 올리면 계정이 제한될 수 있으니 그냥 두시는 게 좋습니다.

**계정이 정지될 위험은 없나요?**
내 블로그의 내 댓글을 지우는 것이고, 사람이 클릭하는 것보다 느린 속도로 보냅니다.
다만 보장할 수는 없습니다. 시험 삭제와 소규모 삭제로 단계를 밟으시기를 권합니다.

**티스토리가 아닌 다른 블로그도 되나요?**
안 됩니다. 티스토리 전용입니다.

**공감(좋아요) 도배도 지울 수 있나요?**
아닙니다. 댓글만 다룹니다.

**다른 기기에서 접속해도 되나요?**
기본값은 로컬 전용입니다. `APP_HOST=0.0.0.0` 으로 열려면 `APP_AUTH_ENABLED=true` 와
비밀번호가 필수이고, 없으면 기동 자체가 거부됩니다. 블로그 계정을 조작할 수 있는 쿠키를
보관하는 서비스라서 공개망 노출은 권하지 않습니다.

## 잘 안 될 때

| 증상 | 원인과 해결 |
|---|---|
| `소유자 인증됨` 이 안 뜹니다 | 로그아웃됐거나 쿠키가 만료됐습니다. 다시 로그인하고 쿠키를 새로 복사해 주세요 |
| 삭제가 계속 실패합니다 | `설정` 에서 1건 시험 삭제를 해 보세요. 여기 나오는 메시지가 티스토리 원문이라 원인 파악이 가장 빠릅니다 |
| 작업이 스스로 멈췄습니다 | 서킷 브레이커가 열렸습니다. `작업 이력` 에서 사유를 보고 해결한 뒤 `재개` 를 누르시면 됩니다 |
| 쿠키를 복호화하지 못합니다 | `.env` 의 `APP_SECRET_KEY` 가 바뀌었습니다. 쿠키를 다시 등록해 주세요 |
| 수집한 댓글이 안 보입니다 | `댓글 관리` 의 상태 필터가 `활성` 인지 확인해 주세요. 이미 지운 건 `삭제됨` 상태입니다 |

```bash
python -m app --reload   # 코드 변경 시 자동 재시작
```

스팸 규칙은 `config/rules.yaml` 에서 바꿉니다. 웹 화면 `설정` 에서도 편집할 수 있고,
저장 전에 검증하므로 잘못된 규칙이 반영되지는 않습니다. 기본값은 **70점 이상 스팸**,
**40점 이상 의심**입니다.

같은 일을 겪은 분에게 도움이 됐으면 좋겠습니다. 이슈나 PR은 환영합니다.
